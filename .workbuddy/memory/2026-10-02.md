## 输出格式：最终定为单一 docx（2026-10-02 核实）

用户要求"别搞这么多，2 选 1"，核心诉求是**产出物要能上云端、任意终端随时看**。
核实飞书官方文档后的结论：

- **手动 UI 导入「导入为在线文档」**：
  - 导入到「我的文档库 / 知识库」：仅支持 `.zip .doc .docx .xls .xlsx .csv .base .pptx .xmind .mm .opml`
  - 导入到「文件夹」：支持 `.doc .docx .md .markdown .mark .txt .xls .xlsx .csv .base .pptx .xmind .mm .opml`
  - 两处**都不含 .html** → HTML 无法通过界面手动导入成云文档。
- 飞书云文档是块式结构，**不能把 HTML 源码塞进去直接渲染**；只在"Web 嵌入/iframe"场景可挂公网 URL，且多有白名单限制。
- 但**开放平台「导入任务」API 底层支持 .html**（第三方 RPA 文档明确列出 `.docx/.doc/.txt/.md/.mark/.markdown/.html`）。
  → 所以 HTML 将来走 API 导入是可能的，但 MVP-0 用户要手动操作，走不通。
- **结论：MVP-0 只产出 `report.docx`**。

## 生成 docx 时的硬性要求（实现时必须遵守）

1. 图片必须**嵌入 docx 包内**（python-docx 的 `add_picture` 天然满足），绝不能用外链或相对路径——否则导入飞书后图会丢。
2. 标题必须用**真正的 Word 标题样式 Heading 1 / Heading 2**，飞书才能识别成一级/二级标题并生成目录大纲；
   自己手敲 `#` 或用加粗大字是不行的。
3. 截图下方必须带「几分几秒」标注，方便用户在原视频复查定位（这是用户明确要的）。
