# 内容阶段怎么做（第 ② 步，没有命令可替代）

这一步占整个流程的时间最多，也决定成品质量。产物是三个文本文件，喂给 `make_content.py` 组装成 `content.json`。

## 拿到素材后先通读

```bash
python - << 'EOF'
import json, pathlib
b = json.loads(pathlib.Path("<视频文件夹>/subtitle.json").read_text(encoding="utf-8"))["body"]
def mmss(s): return f"{int(s)//60:02d}:{int(s)%60:02d}"
out, buf, t0 = [], "", b[0]["from"]
for x in b:
    buf += x["content"]
    if len(buf) >= 38 or x is b[-1]:
        out.append(f"[{mmss(t0)}] {buf}"); buf = ""; t0 = x["to"]
pathlib.Path(".tmp/transcript_raw.txt").write_text("\n".join(out), encoding="utf-8")
EOF
```

**AI 字幕（`ai-zh`）完全没有标点**，一整串汉字。通读时同步做两件事：**断句**和**听写纠错**（实测踩过的：飞书≠非洲、豆包≠豆吧、Seedance≠CDance、AGENTS.md≠AMD）。这一步省不掉。

## 产出三个文件（都放 `.tmp/`）

### 1. `full_blocks.txt` —— 全量文字版

每行一块，**制表符**分隔，冒号前是该块起点：

```
00:00<TAB>开场，今天要讲的是…
01:02<TAB>先说知识库这部分…
```

- 目标 **60 秒左右一块**，但**跟着语义走**，不要机械切：一句话讲到一半宁可让这块长一点
- 参考量：35 分钟 ≈ 40–45 块
- 每块用完整句子写，保留原意，不要压缩成摘要——这是"全量"版

### 2. `chapters.json` —— 总结版章节

```json
[
  {"start": 0,     "end": 104,  "title": "为什么要用知识库",
   "summary": "……", "bullets": ["要点一", "要点二"]},
  {"start": 104,   "end": 312,  "title": "怎么搭 Skills",
   "summary": "……", "bullets": []}
]
```

- `start` / `end` 单位是**秒**，必须首尾相接覆盖全片
- 参考量：35 分钟 ≈ 10–14 章
- `summary` 讲这章到底讲了什么、结论是什么；`bullets` 留操作步骤或要点，**没有就给空数组**，别硬凑

### 3. `images.json` —— 截图点

```json
[
  {"t": 30,  "caption": "本地知识库文件夹结构"},
  {"t": 385, "caption": "8 个模块的可视化面板"}
]
```

**选图判据（红线 5）：只截"文字说不出来的信息"**——界面长什么样、代码怎么写的、图表数据多少、成品 PPT 长什么样。**纯口播对着镜头讲的段落不配图。** 所以时间点是疏密不均的，不是每隔几分钟一张。

参考密度：35 分钟 ≈ 6–12 张。

caption 写画面里那个**信息点**（"豆包的 Skills 创建界面"），不要写"视频截图"。

## 一图流（F14，每篇必做）

在《视频总结版本》**之前**单开一级标题「一图流」，节内只放一张图，不配说明文字（文字都画在图里）。这是导航索引图，让人先看清全片结构、再按图跳正文。

### 核心原则：横向扁宽的「阶段流 + 动作盒」

版式（已由 0001 实测验证，**不要自创**）：

```
┌──────────────────────────────────────────────┐
│ 标题：视频脉络：从一个文件夹到全自动产出（35:35） │
│ 副标题：自绘图 · 按「搭库 → 喂料立规 → 自动化 → 产出」重排 │
└──────────────────────────────────────────────┘
  ① 搭库（0:00-8:37）  [动作盒] → [动作盒] → [动作盒]
        ↓ 竖向箭头递进
  ② 喂料与立规（8:37-12:03）  [动作盒] → [动作盒]
        ↓
  ③ 四个自动化开关（12:03-28:36）  [盒] → [盒] → [盒] → [盒] → [盒]
        ↓
  ④ 产出（全片）   [────────通栏长盒────────]
```

- **横向扁宽**，约 `2000 × 900~1200`。**绝对不要画竖版长图**——竖版会变成长条目录，用户明确判过「这不就是个目录吗」
- **顶部一行标题 + 一行副标题**，副标题点明全片按哪几段重排。**不需要另造「总」这个色块**
- **左侧阶段标签条**：`序号 + 阶段名 + 时间码`，宽度按文字像素自适应（固定宽度会裁字）
- **右侧动作盒横排**，盒间横向箭头串联；**阶段间竖向箭头**向下递进；末段可用通栏长盒收尾
- 每阶段一套配色（底色 + 边框色成对）

### 节点 = 阶段 + 动作盒

| 要素 | 规则 |
|---|---|
| 动作盒主文字 | **你提炼的动作短句**（如「新建「个人知识库」文件夹」「丢入架构师提示词自动搭骨架」）。**不是章节标题逐字** |
| 动作盒副文字 | 补充说明（如「8 模块 + 主地图 + 规则 + 首设清单」） |
| 动作盒 ↔ 章节 | 每个盒记录 `chapters:[idx...]`，**并集必须不重不漏覆盖全部章节** |

### 覆盖校验（红线 9 的机制保障）

脚本启动时**断言**所有动作盒的 `chapters[]` 并集 == `range(len(chapters))`，**漏章或重复归入直接 `sys.exit`，不出图**。

> 实测教训：0001 原有那张图把第 0 章、第 4 章各拆进两个动作盒，同一章被归入两次。**同一章的多个动作应合并进一个盒内多行**（`"main": "动作A → 动作B"`, `"sub": "说明A；说明B"`）。

### 专属脚本要做的六件事

1. **只读 `<video_dir>/content.json`**（**不读 `.tmp/`**，那是仓库根的公共临时区、非 per-video）
2. 断言覆盖，不合法就退出
3. 阶段划分硬编码在脚本的 `STAGES` 里（**你自己判断，不问用户**）
4. **盒宽按可用宽度自适应**：`bw = (BOX_AREA - gap*(n-1)) // n`，固定宽度会溢出画布
5. **标签宽按像素自适应**：`text_size()` 量出文字宽 + padding
6. `--preview` 按 **1000px** 宽缩放另存 `_preview_一图流.png`，**必须 Read 它看过再收工**

### 画之前先扫一眼历史产物

**`data/000N.…/figures/` 里可能已有可复用的版式。** 0001 经历了三次返工，第三次才发现自己项目里早就有一张验证过的 `视频脉络` 图（2000×1120）——重画时忽略了它，白返工两轮。

### 调用顺序（固定，顺序陷阱）

```
① 补 chapters.json 的 phrase → ② make_content.py → ③ 该篇专属一图流脚本 → ④ run_all.py --full
```

`make_content.py` 会**重建** `figures`，抹掉已登记的 overview，所以 ③ 必须在 ② 之后。

## 文中补充图 / 自绘图（F12，可选 0–1 张）

只有当你判断正文某处结构讲不清（如局部对比、步骤流程）时才画，**每篇 0–1 张**；全片脉络已由 F14 一图流承担，这里**不重复画总脉络**。

- `scripts/draw_onepager_0001.py` 也是可抄的参考（PIL + `C:/Windows/Fonts/msyh.ttc`，输出 PNG 到 `figures/`）
- 画完**必须生成缩略图给自己看一眼**（常见问题是文字被框挤出去、或盒宽溢出画布）
- ⚠ `scripts/draw_figure_0001.py` **已删除**（它硬编码、且与一图流职责重叠）。全片脉络只由 F14 一图流承担

## 组装

```bash
"$PY" "$REPO/scripts/make_content.py" --dir "data/000N.《标题》" \
    --blocks .tmp/full_blocks.txt --chapters .tmp/chapters.json --images .tmp/images.json \
    --figure "figures/xxx.png|图说明"
```

脚本会按时间区间**自动把截图分配给章节和段落块**——同一张图文件在总结版和全量版都出现，这是刻意的：两个版本都该能看见画面。输出末尾若提示"未落入任何章节"，说明那张图的时间点落在了 chapters 覆盖范围外，检查一下起止秒。

然后到第 ③ 步 `--full`：抽帧 → docx → 云文档。渲染阶段 `render_feishu.py` 会先读 `视频信息.md` 里已有的飞书链接：有则整篇覆盖更新同一篇、无则新建，所以重跑同一视频不会多生成文档（飞书自带版本历史可回滚）。

## 交付前自查

- 抽完帧**逐张用缩略图核对**，确认确实拍到了想要的信息；时刻偏了就改 `images.json` 重抽，别将就
- 收尾：本地 docx 存在、云文档生成成功、链接已写回 `视频信息.md`
