# 设计文档

> 项目代号：让 AI 学会看 B站视频
> 定位：**不追求详尽，只锁定方向和功能边界**。细节在实现时补，不预先编造。
> 相关文档：新手先读根目录 `《新手刚拿到此项目最先阅读》.md`（使用流程 + 简版原理）；本篇是规范与选型的唯一真相源。

---

## 1. 一句话目标

给我一个 B站视频链接 → 产出一份**可以直接在飞书里读**的文档：有全量文字版、有按内容分章节的总结、关键处配截图和时间码，我不用再打开原视频。

## 2. 为什么自己造（现成工具的缺口）

调研结论（2026-10）：

| 能力 | 现成工具 | 说明 |
|---|---|---|
| 下载 B站视频 | ❌ | 通义听悟、飞书妙记均不支持贴链接（合规），必须下载后上传 |
| 全量文字版 | ✅ | 妙记免费档 300 分钟/月，但**只给逐字稿** |
| 章节总结 | ❌ | 妙记「智能纪要」需付费；其余工具多为会议纪要式模板，套在长视频上很别扭 |
| 截图 + 几分几秒 | ❌ | **没有任何现成工具做** |
| 云端随时看 | ✅ | 云文档直写，产物天然在飞书；docx 仅作本地兜底 |

**结论**：免费工具只覆盖了最不缺的一环（转写），真正想要的总结与截图是空白。且用量越大（只看长视频），自建越划算——字幕走 B站官方 AI 字幕，边际成本为 0。

## 3. 总体流程

```
B站链接
  → ① 解析 BV 号 / 分 P
  → ② 下载视频本体（720P）
  → ③ 抓取字幕（人工 CC 优先，无则 B站 AI 字幕；wbi 签名 + SESSDATA 登录态）
  → ④ 由 WorkBuddy 读字幕：按内容分段 + 逐段总结 + 标出值得截图的时刻
  → ⑤ 按时间码精确抽帧（本地 frames/）
  → ⑥ 生成「中间内容结构」（章节 / 段落 / 图片 / 时间码，与排版无关的一份数据）
  → ⑦ 双渲染输出（两份同名：`0001.《视频标题》`）
        ├─ 渲染到飞书：lark-cli 用户身份直写 → 云文档落到「009.AI生成文档」文件夹 → 链接写回 视频信息.md
        └─ 渲染到本地：python-docx → `0001.《视频标题》.docx`（副本 / 兜底）
```

**为什么是「中间结构 + 双渲染」**：内容只构建一次，出口两套。避免飞书版与 docx 版各写一套逻辑而走样；飞书那头挂了，本地 docx 已是成品，不用重跑。

## 4. 目录与文件规范

每个视频一个自包含文件夹，编号 4 位递增，空号不复用：

```
data/
└─ 0001.《视频标题》/
    ├─ video.mp4          视频本体（720P）
    ├─ subtitle.json      B站原始字幕（精确起止秒）
    ├─ subtitle.srt       通用字幕格式
    ├─ 视频信息.md        原链接 / BV号 / 标题 / UP主 / 时长 / 抓取时间
    ├─ frames/            视频截图，文件名带时间码（00-05-12.jpg）
    ├─ figures/           自绘结构图（SVG 源 + PNG），如思维导图 / 流程图 / 对比表
    └─ 0001.《视频标题》.docx   本地副本（图片内嵌），飞书版失败时即为兜底成品
```

- **统一命名（2026-10-02 变更）**：本地 docx 与飞书云文档**都命名为 `0001.《视频标题》`，与文件夹完全同名**——看到名字就知道编号和视频，本地云端一一对应
- **双产物**：飞书云文档是主产物，其链接写回 `视频信息.md`；本地 docx 是副本，每次都生成
- **不再产出 `笔记.md`**：有内嵌图片的 docx 兜底，纯文本版无意义
- **飞书云文档位置**：固定创建在云盘「**个人新文件夹 › 009.AI生成文档**」文件夹内（folder token `UVPlfB43RlbpvIdg76jcsH6Ynng`，存于 `.secrets/feishu_folder.txt`，不入库）
- **文档内容**：正文开头写明**视频原链接**（可点击），方便随时跳回原视频；**本地 docx 与飞书云文档两份都要写**（见质量红线第 2 条）
- **命名清洗**：去掉 Windows 非法字符 `\/:*?"<>|`，标题超过 60 字截断加 `…`
- **重复链接**：同一 BV 号已存在 → 提示「已存在（0001）」，不重复下载、不新建编号
- **分 P 视频**：默认只处理链接指定的那一 P；链接不带 P 号而视频是多 P 时，先提示选择
- **产物位置**：报告与截图都放在该视频自己的文件夹内，不另建 `outputs/`

| F11 | 长视频分块 | 超长字幕自动按长度分块处理再合并（无需用户干预） | MVP-0 |

### 截图的选点与分配（F7 细则）

- **选点逻辑**：由 WorkBuddy 读完**全量文本**后再决定哪里值得截图，不是均匀分布、不为美观
- **判据**：只取「**文本给不出的精确信息**」——界面长什么样、代码怎么写的、操作步骤、图表数据。纯口播内容不截图
- **数量**：35 分钟量级视频 **6–12 张**；更长视频按比例增加，但不铺张
- **分配**：《视频总结版本》是配图主战场（每段 1–3 张）；《视频全量文字版》**也要配图**，插在该精华点所属的段落块下方
- **去重**：同一时间点只抽一帧；同一段内候选点间隔 **<10 秒**的合并；同一张图在全量版与总结版复用同一份文件（不重复抽帧、不重复上传）
- **抽帧命令**：`ffmpeg -ss <t> -i video.mp4 -frames:v 1 -q:v 2 out.jpg` —— **`-ss` 必须放在 `-i` 前面**（先定位再解码）；放 `-i` 后面会变成逐帧解码到目标位置，慢一个数量级

## 6. 技术选型

| 环节 | 方案 | 理由 |
|---|---|---|
| 视频获取 | `yt-dlp` | 稳定、纯 pip，不需装系统软件 |
| 音视频处理 | `imageio-ffmpeg` | pip 包自带 ffmpeg 二进制，**换台电脑也能跑** |
| 文字来源 | B站字幕：**人工 CC 优先，无则 AI 字幕** | 零成本、秒级；CC 与 AI 字幕结构一致，产出文件完全统一 |
| 登录凭证 | `SESSDATA` 存 `.secrets/` | 已 gitignore，绝不入库；**获取走官方扫码登录接口（半自动），详见下节** |
| 总结 | **由 WorkBuddy 在对话中完成** | 不用配 LLM Key，零额外成本，质量优于模板化摘要 |
| 内容表示 | 中间内容结构（JSON）→ 双渲染器 | 一次构建、两种出口，避免两份逻辑走样 |
| 本地渲染 | `python-docx` | 真标题样式、图片内嵌；**中文字体须显式设 eastasia，否则显示方框** |
| 云端渲染 | `lark-cli`（lark-unified 套件）**用户身份**直写 block + 素材上传 | 唯一能「一步到位云文档」的路径（导入 API 必须接收文件，故不适用）；**已实测跑通** |
| 自绘结构图 | SVG 手绘 → PNG 落盘（`figures/`） | 矢量可控、可嵌入 docx 与飞书；**中文同样需指定字体**，否则方框 |

### 关于 ASR（已整体放弃，留档备查）

在确认「B站 AI 字幕可直取」之前，评估过三条语音转文字路线。**最终全部作废**，留档是为了避免将来重复调研：

| 方案 | 免费额度 | 状态 |
|---|---|---|
| 硅基流动 `SenseVoiceSmall` | 输入/输出均免费 | 需注册拿 Key |
| 阿里云百炼 `paraformer-v2` | 每月 10 小时免费 | 备选额度 |
| 本地 `faster-whisper` | 完全免费离线 | 慢，且绑本机显卡 |

**作废原因**：B站官方字幕零成本、秒级、准确度更高，且自带精确时间戳——ASR 这一整环没必要存在。
**重新启用的条件**：大量遇到无字幕视频，且用户愿意接受等待或注册成本。**届时红线 1 也要一并重新拍板**（当前是「无字幕即中止」，与自动 ASR 降级互斥）。

### 依赖与「换台电脑也能跑」

全部依赖都是 pip 包或随项目走的凭据，**不装任何系统软件**（尤其不需要单独装 ffmpeg、不需要显卡）：

```
requirements.txt:  yt-dlp / imageio-ffmpeg / requests / python-docx
外部命令:          lark-cli（由 lark-unified 套件提供，飞书写入用）
本机凭据(不入库):  .secrets/sessdata.txt（B站）、.secrets/feishu_folder.txt（云盘文件夹 token）、~/.lark-cli/config.json（飞书凭证）
```

换机步骤：`git clone` → `pip install -r requirements.txt` → 补三个凭据 → 可用。
**运行时会打印阶段日志**（下载走 yt-dlp 进度条），满足"能看到进度才踏实"。

### 飞书写入的实现方式（已实测跑通 2026-10-02）

**采用方案**：市场安装 `lark-unified` 套件（内含官方 `lark-cli`），走**用户身份（user）**授权，不需要手动创建自建应用。

| 环节 | 做法 |
|---|---|
| 应用凭证 | `lark_setup.py` 设备码流程自动注册应用并保存配置到 `~/.lark-cli/config.json`（App ID `cli_aa358d94c978dbc1`）；**不入库** |
| 用户授权 | `lark-cli auth login --scope "docx:document:create docx:document:write_only docx:document:readonly docs:document.media:upload docs:document.media:download drive:file" --no-wait --json` → 用户点授权页 → `auth login --device-code <code>` 完成 |
| 建文档 | `docs +create --as user --parent-token <云盘文件夹token> --content @xxx.xml`（内容为 XML：`<title>` / `<h1>` / `<h2>` / `<p>`）→ 返回 `document_id` 与云文档 URL；**--parent-token 指定云盘「009.AI生成文档」文件夹，已实测** |
| 插图 | `docs +media-insert --as user --doc <id> --file ./x.jpg --caption "📍 00:05:00" --width 800` → 自动上传素材并插入 image block |

**实测结论**：

- 文档**直接创建在个人云空间**（`my.feishu.cn`），无需再做协作者授权 —— 这是选用户身份而非 bot 身份的主要原因
- H1/H2 层级、正文、图片及 caption 均正确落地；`--parent-token` 放进「009.AI生成文档」文件夹也已验证（两篇验证文档**已删除**，云盘已恢复干净）
- bot 身份会报 `app_scope_not_applied`（99991672），除非去开放平台给应用申请 `docx:document` 权限；**本项目不走这条**

**已知坑（Windows）**：

1. `lark-cli` 是 `.cmd` 脚本，Python `subprocess` 无法直接执行 → `WinError 2`。必须用 `node.exe` + `node_modules/@larksuite/cli/scripts/run.js` 调用（已修进 skill 的 `lark_cli_base_cmd()`）
2. 设备码授权必须**同一次流程内轮询**取凭证；只生成 URL 而不 `--device-code` 轮询，用户点了也拿不到凭证
3. `--file` / `--content @file` 只接受 **cwd 相对路径**，绝对路径会被拒绝

### B站登录凭证（SESSDATA）的获取与失效处理

**没有 B站连接器**（已在 WorkBuddy 市场确认），所以无法像飞书那样一键授权。但有官方扫码登录接口，可做**半自动**：

| 步骤 | 做法 |
|---|---|
| ① 申请二维码 | `GET passport.bilibili.com/x/passport-login/web/qrcode/generate` → 拿到 `qrcode_key` 与扫码 URL（**已实测可用**） |
| ② 用户扫码 | 把二维码 / 链接给用户，**用 B站 App 扫码确认** |
| ③ 轮询取凭证 | 轮询 passport 登录态接口，成功后从响应 cookie 中提取 `SESSDATA`，写入 `.secrets/sessdata.txt` |

- **等价性**：扫码登录拿到的 `SESSDATA` 与手动从浏览器复制的是同一种凭证，权限完全一致
- **失效时**：脚本必须明确报「**SESSDATA 失效，请重新获取**」并直接给出重新扫码的引导，**绝不静默产出空字幕**
- **兜底**：扫码接口若被风控或改版，回退到手动复制（F12 已有流程说明：F12 控制台 → Application → Cookies → SESSDATA）

### 自绘结构图的规则（F12）

**不是每篇都画，由 WorkBuddy 读完内容后判断值不值。** 判据是：这张图能否让读者少看两千字——能就画，不能就不画（宁缺毋滥）。

| 内容特征 | 画的图 | 放在哪 |
|---|---|---|
| 讲了几个并列方面 / 概念有层级 | **思维导图**（知识结构） | 总结版开头 |
| 是操作教程 / 有先后顺序（如搭流程、配置步骤） | **流程图 / 步骤图** | 对应章节下 |
| 有多个方案 / 参数 / 工具对比 | **对比表**（优先用表格，比图更好编辑） | 对应章节下 |
| 全片脉络跨时长 | **章节时间轴** | 总结版开头 |

- **数量**：每个视频 0–2 张，不贪多
- **红线**：图必须有**信息增量**——不能是把正文文字换了个排版重画一遍；纯装饰性的一律不画
- **与截图的区分**：截图 = 视频里**出现过**的真实画面；自绘图 = 视频里**没有**、由我归纳出来的结构。两者互补，不互相替代

## 7. 明确不做

- Web 界面 / 浏览器插件（先命令行）
- 批量队列、并发、断点续跑
- **ASR 语音转写 —— 当前完全不做**：无字幕即中止（红线 1）。曾评估过三条备选方案（见第 6 节留档），因 B站字幕可直取而整体作废；将来若大量遇到无字幕视频，需重新拍板才能启用
- 多格式产物（HTML 预览 / Markdown 副本）—— 只保留一份本地 docx 兜底，**不再产出 `report.md`、`笔记.md` 等其他形态**
- **追加写入已有云文档** —— 当前只新建，不往已有文档里追加内容
- 多语言翻译、双语字幕
- 视频内容问答 / RAG 知识库
- 结构化导出（多维表格、JSON schema）

### 使用边界与合规

- **定位**：个人学习自用，一次处理 4–5 个视频的量级（用户明确表示不批量）
- **不批量爬取站点**，不处理需要付费或授权的内容
- 下载的视频与字幕**仅本地使用、不外传**；截图中若含个人信息需注意
- 飞书与 B站凭据只存本机，不入库、不上传

## 8. 质量红线（不达标就报错，不静默出货）

1. **无任何字幕（CC 与 AI 都没有）→ 直接报错中止**，不静默降级、不产出残缺文档
2. **文档开头必须有可点击的视频原链接**——本地 docx 与飞书云文档**两份都要写**，缺了即判不合格（这是随时跳回原视频复查的唯一入口）
3. 总结每一节必须落到具体时间点；编不出来则按时间戳等分兜底
4. 文档里每张图必须带「几分几秒」标注，无标注的图不许进文档
5. **截图只取「文本给不出的信息」**（界面、代码、操作步骤、图表），不为美观、不按时间均匀分布
6. **自绘图必须有信息增量**，不能是正文的重新排版；内容撑不起一张图时就不画
7. docx 必须用真 Heading 样式（不是加粗），否则飞书不生成大纲；图片必须内嵌，不能外部引用
8. 飞书写入失败必须明确报错，且**本地 docx 必须已经生成完毕**，不允许白跑
