# 设计文档

> 项目代号：让 AI 学会看 B站视频
> 定位：**不追求详尽，只锁定方向和功能边界**。细节在实现时补，不预先编造。

---

## 1. 一句话目标

给我一个 B站视频链接 → 产出一份**可以直接在飞书里读**的文档：有全量文字版、有按内容分章节的总结、关键处配截图和时间码，我不用再打开原视频。

## 2. 为什么自己造（现成工具的缺口）

调研结论（2026-10）：

| 能力 | 现成工具 | 说明 |
|---|---|---|
| 下载 B站视频 | ❌ | 通义听悟、飞书妙记均不支持贴链接（合规），必须下载后上传 |
| 全量文字版 | ✅ | 妙记免费档 300 分钟/月，但**只给逐字稿** |
| 章节总结 | ❌ | 妙记「智能纪要」需付费；其余工具多为会议纪要式模板，套在长视频上很别扭 |
| 截图 + 几分几秒 | ❌ | **没有任何现成工具做** |
| 云端随时看 | ✅ | docx 导入飞书即可达成 |

**结论**：免费工具只覆盖了最不缺的一环（转写），真正想要的总结与截图是空白。且用量越大（只看长视频），自建越划算——字幕走 B站官方 AI 字幕，边际成本为 0。

## 3. 总体流程

```
B站链接
  → ① 解析 BV 号 / 分 P
  → ② 下载视频本体（720P）
  → ③ 抓取字幕（人工 CC 优先，无则 B站 AI 字幕；wbi 签名 + SESSDATA 登录态）
  → ④ 由 WorkBuddy 读字幕：按内容分段 + 逐段总结 + 标出值得截图的时刻
  → ⑤ 按时间码精确抽帧（本地 frames/）
  → ⑥ 生成「中间内容结构」（章节 / 段落 / 图片 / 时间码，与排版无关的一份数据）
  → ⑦ 双渲染输出
        ├─ 渲染到飞书：Block API 直写 → 云文档链接 → 写回 视频信息.md
        └─ 渲染到本地：python-docx → 《简短标题》.docx（副本 / 兜底）
```

**为什么是「中间结构 + 双渲染」**：内容只构建一次，出口两套。避免飞书版与 docx 版各写一套逻辑而走样；飞书那头挂了，本地 docx 已是成品，不用重跑。

## 4. 目录与文件规范

每个视频一个自包含文件夹，编号 4 位递增，空号不复用：

```
data/
└─ 0001.《视频标题》/
    ├─ video.mp4          视频本体（720P）
    ├─ subtitle.json      B站原始字幕（精确起止秒）
    ├─ subtitle.srt       通用字幕格式
    ├─ 视频信息.md        原链接 / BV号 / 标题 / UP主 / 时长 / 抓取时间
    ├─ frames/            截图，文件名带时间码（00-05-12.jpg）
    └─ 《简短标题》.docx   本地副本（图片内嵌），飞书版失败时即为兜底成品
```

- **双产物**：飞书云文档是主产物，其链接写回 `视频信息.md`；本地 `《简短标题》.docx` 是副本，每次都生成
- **不再产出 `笔记.md`**：有内嵌图片的 docx 兜底，纯文本版无意义
- **docx 命名**：不用固定的 `report.docx`，用**真实视频标题的精简版**（≤20 字左右，可按内容概括，但必须与原视频标题有呼应，看到文件名就能对上是哪个视频）；例：`0001.《【豆包实操】从个人知识库到自动化：…》/` 里放 `《豆包实操：知识库到自动化》.docx`
- **文档内容**：正文开头写明**视频原链接**（可点击），方便随时跳回原视频
- **命名清洗**：去掉 Windows 非法字符 `\/:*?"<>|`，标题超过 60 字截断加 `…`
- **重复链接**：同一 BV 号已存在 → 提示「已存在（0001）」，不重复下载、不新建编号
- **分 P 视频**：默认只处理链接指定的那一 P；链接不带 P 号而视频是多 P 时，先提示选择
- **产物位置**：报告与截图都放在该视频自己的文件夹内，不另建 `outputs/`

## 5. 主要功能清单

| # | 功能 | 说明 | 阶段 |
|---|---|---|---|

| F5 | 全量文字版 | **按语义段落块**（约 60 秒一块，优先语义连贯）输出，块首带时间戳，一级标题《视频全量文字版》 | MVP-0 |

| F12 | 一键串联 | 一条命令跑完 F1–F4，后续步骤交给对话 | 后续 |

## 6. 技术选型

| 环节 | 方案 | 理由 |
|---|---|---|
| 视频获取 | `yt-dlp` | 稳定、纯 pip，不需装系统软件 |
| 音视频处理 | `imageio-ffmpeg` | pip 包自带 ffmpeg 二进制，**换台电脑也能跑** |
| 文字来源 | B站字幕：**人工 CC 优先，无则 AI 字幕** | 零成本、秒级；CC 与 AI 字幕结构一致，产出文件完全统一 |
| 登录凭证 | `SESSDATA` 存 `.secrets/` | 已 gitignore，绝不入库 |
| 总结 | **由 WorkBuddy 在对话中完成** | 不用配 LLM Key，零额外成本，质量优于模板化摘要 |
| 内容表示 | 中间内容结构（JSON）→ 双渲染器 | 一次构建、两种出口，避免两份逻辑走样 |
| 本地渲染 | `python-docx` | 真标题样式、图片内嵌；**中文字体须显式设 eastasia，否则显示方框** |
| 云端渲染 | 飞书 Block API 直写 + 素材上传 | 唯一能「一步到位云文档」的路径（导入 API 必须接收文件，故不适用） |

### 飞书写入的前置条件与已知坑

- **硬门槛**：需飞书自建应用的 **App ID / App Secret**（开放平台创建，开通 `docx:document`、`drive:file` 等权限并发布版本）
- **文档归属**：API 创建的文档默认在应用空间，需再「添加协作者」授权给个人账号，才能在「我的云文档」中看到
- **图片上传**：先调素材上传接口拿 `file_token`，再插入 image block；截图因此必须先落到本地 `frames/`
- **待验证**：个人版（`my.feishu.cn`）能否创建自建应用；Block 渲染的实际排版效果需实测一次

## 7. 明确不做

- Web 界面 / 浏览器插件（先命令行）
- 批量队列、并发、断点续跑
- ASR 本地转写（除非某视频确实无 AI 字幕）
- 多语言翻译、双语字幕
- 视频内容问答 / RAG 知识库
- 结构化导出（多维表格、JSON schema）

## 8. 质量红线（不达标就报错，不静默出货）

1. **无任何字幕（CC 与 AI 都没有）→ 直接报错中止**，不静默降级、不产出残缺文档
2. 总结每一节必须落到具体时间点；编不出来则按时间戳等分兜底
3. 文档里每张图必须带「几分几秒」标注，无标注的图不许进文档
4. **截图只取「文本给不出的信息」**（界面、代码、操作步骤、图表），不为美观、不按时间均匀分布
5. docx 必须用真 Heading 样式（不是加粗），否则飞书不生成大纲；图片必须内嵌，不能外部引用
6. 飞书写入失败必须明确报错，且**本地 docx 必须已经生成完毕**，不允许白跑

## 9. 里程碑

- **M0（当前）**：F1–F4 跑通 —— 给链接就得到一个整齐的素材文件夹
- **M1**：F5–F9 / F11 跑通 —— 从素材到本地 docx（先验证内容质量与排版）
- **M2**：F10 跑通 —— 同一次构建同时产出飞书云文档，链接写回 `视频信息.md`
- **M3**：F12 一键串联
