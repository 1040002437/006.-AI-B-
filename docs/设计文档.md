## 2. 总体架构

采用**单进程管道（Pipeline）**架构，阶段之间用磁盘上的中间产物解耦，便于断点重跑与单阶段调试。

```
[输入] BV号/链接
   │
   ▼
① 元数据获取 ──────► meta.json（标题、UP主、时长、简介、封面）
   │
   ▼
② 媒体下载 ───────► video.mp4 / audio.m4a
   │
   ▼
③ 音频转写(ASR) ───► transcript.srt / transcript.txt（带时间戳）
   │
   ▼
④ 视觉抽帧 ────────► frames/*.jpg（关键帧 + 时间戳）
   │
   ▼
⑤ 多模态理解 ──────► segments.json（分段语义、关键画面描述）
   │
   ▼
⑥ 结果合成 ────────► report.md / report.json（摘要、章节、结论）
   │
[输出] report.md
```

### 为什么这样切

- **可断点**：每阶段产物落盘，重跑不必重下视频（下载是最慢最贵的一步）。
- **可替换**：ASR 引擎、视觉模型、LLM 都是可插拔的 Stage，不必重写全流程。
- **可测试**：每个 Stage 都能独立喂样例输入做单测。

## 7. 风险与约束

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| B 站接口/下载工具失效 | 全流程中断 | 依赖版本锁定；失败快速报错而非静默降级 |
| 长视频导致成本与时延失控 | 不可用 | 设置时长上限与抽帧密度上限 |
| ASR 中文识别质量不足 | 理解失真 | 允许热词表；保留原始音频便于重处理 |
| 中间产物占磁盘 | 磁盘爆炸 | `data/` 进 .gitignore，提供清理命令 |
